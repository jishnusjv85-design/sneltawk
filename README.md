# Snel Tawk → Make.com → Freshdesk

Primary automation for creating Freshdesk tickets from Tawk without using the `tawk.t8t.bar` bridge.

## Required flow

Customer → Tawk chat/chatbot → Tawk `New Ticket` webhook → Make.com → Freshdesk `Create a Ticket`

The goal is to create the Freshdesk ticket with the customer's real email address as the requester.

Do **not** use Tawk's Ticket Forwarding Email to create the same Freshdesk tickets. That route can create duplicates and may use a Tawk relay/generated address instead of the customer's actual email.

## 1. Create the Make.com scenario

In Make.com:

1. Create a new scenario.
2. Add **tawk.to** as the first module.
3. Select **Watch New Ticket**.
4. Create a new webhook and name it, for example `Snel Tawk Freshdesk`.
5. Save the webhook and copy the generated Make webhook URL.

## 2. Configure Tawk

In **Tawk → Administration → Settings → Webhooks**:

1. Create a webhook.
2. Name it `Make - Freshdesk Tickets`.
3. Paste the webhook URL generated by Make.
4. Select **New Ticket** as the event.
5. Save.

Tawk's new-ticket payload includes:

- `requester.name`
- `requester.email`
- `ticket.subject`
- `ticket.message`
- `ticket.id`
- `ticket.humanId`
- property information

## 3. Capture the customer's real email

The chatbot must collect the visitor's email **before** it creates the Tawk ticket.

Preferred result:

- Tawk `requester.email` = the customer's real email.

For additional safety, include the email in the ticket body when your chatbot workflow allows it:

```text
Customer email: customer@example.com
```

This lets the Make scenario fall back to an email extracted from the ticket message if Tawk substitutes a relay/generated requester address.

## 4. Add a Make filter

Before the Freshdesk module, add a filter so tickets are not created with known Tawk relay addresses.

Allow only when the resolved customer email:

- is not empty
- contains `@`
- does not end with `@tawk.to`
- does not end with `@tawk.email`

If `requester.email` is a Tawk relay address, extract the email from `ticket.message` instead when the chatbot included `Customer email:` in the ticket message.

Recommended resolved-email logic:

1. Use `requester.email` when it is a normal customer email.
2. Otherwise use the email extracted from `ticket.message`.
3. If neither produces a real customer email, stop the route and do not create the Freshdesk ticket.

## 5. Add Freshdesk to Make

Add **Freshdesk → Create a Ticket** after the filter.

Create a Freshdesk connection using:

- Freshdesk domain/company: `snel`
- Freshdesk account: `https://snel.freshdesk.com`
- Freshdesk API key from **Freshdesk → Profile Settings → View API key**

Never place the API key in Tawk or in ticket content.

## 6. Freshdesk field mapping

Map the Freshdesk `Create a Ticket` module as follows:

| Freshdesk field | Make/Tawk value |
| --- | --- |
| Email / Requester email | **Resolved customer email** |
| Name | `requester.name` |
| Subject | `ticket.subject` |
| Description | `ticket.message` |
| Status | Open |
| Priority | Low or your preferred default |

Optionally append troubleshooting metadata to the description:

```text
---
Source: Tawk via Make.com
Tawk ticket ID: {{ticket.id}}
Tawk ticket number: {{ticket.humanId}}
Customer email: {{resolved customer email}}
```

## 7. Disable the old forwarding path

After the Make scenario passes testing, disable the old Tawk **Ticket Forwarding Email → Freshdesk** configuration.

Otherwise two Freshdesk tickets can be created:

1. one correct ticket from Make.com
2. one incorrect/duplicate ticket from the Tawk forwarding address

The Vercel/Python bridge in this repository is now a **legacy fallback only** and is not required for the Make.com setup.

## 8. Test the complete workflow

1. In Make, click **Run once**.
2. Start a new Tawk chat as a test visitor.
3. Enter a real test customer email.
4. Ask the chatbot to create a ticket.
5. Confirm Make receives the `New Ticket` event.
6. Inspect `requester.email`, `ticket.subject`, and `ticket.message` in the Make execution.
7. Confirm the filter resolves the real customer email.
8. Confirm Freshdesk creates exactly one ticket.
9. Confirm **Requester** in Freshdesk is the customer's actual email.
10. Reply from Freshdesk and verify the reply goes to that customer email.
11. Turn the Make scenario **ON** after the test succeeds.

## Legacy bridge

The existing Python/Vercel files are intentionally retained as a fallback. They are not part of the primary production flow once Make.com is enabled.
